# TEST-001 — Test Strategy

## Purpose

Defines the complete test strategy for the wicked-estate Unified Foundation (v0.13.0). Specifies test scenarios, layers, evidence requirements, and success criteria for all 23 MCP tools (24 with embedder), backward-compatibility contracts, store lifecycle, skills, and prompts. This document is the normative reference for the Build phase test implementation.

---

## §1 — Test Layers

### 1.1 — Unit Tests (per-crate, `#[cfg(test)]`)

**Scope:** Internal logic of each new crate. Not MCP-level — trait method correctness, store schema, error handling.

**Coverage target:** 80% line coverage per crate measured via `cargo llvm-cov`.

**Crates requiring unit test suites:**
- `wicked-estate-overlay` — XedgeStore open/close, link/unlink, epoch assertion; `XedgeStore::sweep_stale(current_epochs: &HashMap<String, u64>)` removes edges where the stored epoch differs from the provided map and returns the removed count (REQ-003 §5.4: normative API contract method, distinct from the reader-side epoch drop tested by IT-050); additionally seed one current-epoch edge alongside the stale edges and assert it REMAINS in xedge.db after sweep_stale runs (verifying the one-directional nature of the condition — stale edges removed, current edges retained; an over-deleting implementation that removes all edges passes the removed-count check but fails when the current-epoch edge also disappears); FOLD method foreign node annotation — calling `traverse`/`traverse_multi`/`neighbors` after seeding xedge entries from both memory and knowledge engines asserts each returned item has `engine_id: String`, `node_id: String`, `kind: "foreign"`, `label: String`, and `body_snippet: String` fields per REQ-003 §§5.1 and 5.3 (the five-field ForeignNode contract is normative per REQ-003 §5.3: `{ engine_id, node_id, label, body_snippet, kind }`; asserting only the first three fields misses label and body_snippet, allowing a FOLD implementation that calls fetch_node() but discards the label and body_snippet to pass the unit test while violating the full contract) **(§1.1 HC-007 scope note: `traverse`, `traverse_multi`, and `neighbors` are Rust method names on the `XedgeStore` overlay trait — they are NOT MCP tool names; HC-007 frozen goldens cover MCP tools only (`TraverseGraph`, `BlastRadius`, `Lineage`); no HC-007 param-name cross-check applies to these §1.1 unit-test prescriptions (BC-R20-001))**; FOLD stale-epoch drop — seed an about-edge at epoch=N; call `traverse`, `traverse_multi`, or `neighbors` on that symbol and assert the foreign entry IS present (non-empty result — pre-verification step, same two-step pattern as IT-050 Step 1, to rule out a false pass where the about-edge was never written); bump the estate symbol epoch to N+1 (via `UPDATE symbols SET gen = gen + 1 WHERE sym = ?` on estate.db); call `traverse_multi` on that symbol for this specific step — mandating `traverse_multi` here verifies its fold path drops stale about-edges (REQ-003 §5.1: "same fold logic as traverse"; other FOLD steps in this test may use traverse or neighbors freely; this one post-bump step mandates traverse_multi to verify the shared code path is actually invoked (R20-SIG-1)); assert the foreign entry is absent from the result (REQ-003 §5.2: stale about-edges must be dropped by all FOLD methods); assert a WARN-level log line is emitted (same Wave A prerequisite as IT-050/052: overlay.rs epoch-drop path must use `tracing::warn!`, not `eprintln!`); FOLD absent-symbol drop — seed sym_B in estate.db via `SqliteStore::upsert_nodes` and write an about-edge for sym_B (using the unit test equivalent of memory.capture(about=['sym_B']) against the XedgeStore directly); verify edge resolves (call `traverse`, `traverse_multi`, or `neighbors` on sym_B, assert foreign entry IS present — pre-verification step, same pattern as FOLD stale-epoch drop above); then delete sym_B's nodes row from estate.db (same procedure as IT-052 Step 2: `SELECT sid FROM symbols WHERE sym = ?` to capture sym_B's integer sid, then `DELETE FROM nodes WHERE symbol = sid`, leave `symbols` intern row intact — do NOT delete from `symbols`); call `traverse`, `traverse_multi`, or `neighbors` on sym_B; assert foreign entry absent and WARN emitted (same Wave A prerequisite as IT-050/052/stale-epoch: overlay.rs absent-symbol path must use `tracing::warn!`) — tests REQ-003 §5.2 condition 4 at the unit level, complementing IT-052 which covers the same condition via the `recall_about_code` integration path
- `wicked-estate-memory-core` — RecallQuery, budget_pack, MemoryCoverage construction
- `wicked-estate-memory` — MemoryEngine: capture, recall, reflect, erase, learn, coverage (all 6 MemoryApi methods); negative case: erase with empty scope_prefix must return Err (CRIT-7)
- `wicked-estate-knowledge` — KnowledgeEngine: ingest, write, relate, recall, coverage, relate_code, recall_about_code (all 7 KnowledgeApi methods); negative case: relate with non-existent src/tgt node must return Err (CRIT-8)
- `wicked-estate-mcp` — dispatch routing (unit-level, mock stores); SC-008 no-op store compilation (CRIT-2). **Note:** The SC-008 test file (`crates/wicked-estate-mcp/tests/no_op_stores.rs`) lives in the integration tests directory, not in `src/#[cfg(test)]`, because it must link against the full dispatch handler. It is fully specified in §1.3 but listed here because it tests dispatch trait coupling, a unit-level contract.

Each new crate uses `tempfile::tempdir()` for SQLite stores in tests — no shared state between test cases.

### 1.2 — Integration Tests (`crates/wicked-estate-mcp/tests/`)

**Scope:** Full JSON-RPC stdio request/response cycle against real SQLite stores. All 4 stores open in a single process per test case. Tests call `handle_request_unified` directly with real store handles (faster than subprocess — subprocess-level smoke tests live in §1.7). Exceptions: IT-004, IT-005d, IT-007/IT-007b/IT-007c, IT-016, IT-017, and IT-040 are subprocess-level by necessity (fd inspection, startup stderr capture before the stdio loop, signal delivery, stdin-EOF shutdown, environment-variable isolation, concurrent-write interleaving via async stdio, and stdout observation require a real child process and cannot be exercised through direct calls) despite being listed here. IT-016b (unlike IT-016) MAY be implemented in-process with `#[serial_test::serial]` and `remove_var` cleanup per its row description — it is NOT in the subprocess-only list.

**Required integration scenarios:**

#### 1.2.2 — Memory Domain (6 tools)

**Tier word-form enum (HC-007 frozen) — use these string values in API calls, NOT T-codes:**
`"working"` (T0), `"episodic"` (T1), `"semantic"` (T2), `"procedural"` (T3), `"archival"` (T4).
`memory.recall` uses `token_budget: u32` for result-budget control, NOT `limit`.
`memory.learn` uses `symbols: Vec<String>` for code-entity links, NOT `about` (`about` is the `memory.capture` param — both confirmed from HC-007 golden schemas).
`memory.learn` tier is constrained to `["semantic", "procedural"]` only (T2/T3 — NOT working/episodic/archival). Passing any other tier value returns a validation error per HC-007 frozen golden schema.
**REQ-003 §2.2 vs HC-007 divergence for memory.learn:** REQ-003 §2.2 documents the memory.learn content parameter as `fact: String`; the HC-007 golden schema uses `content` (same key as memory.capture). The HC-007 golden is authoritative; all test implementations use `content` as the memory.learn parameter name (same format as the §1.2.3 ContextBundle divergence note added in v0.20) (REQ-M1).

| ID | Scenario | Pass criterion |
|---|---|---|
| IT-010 | memory.capture → memory.recall round-trip (scoped): call `memory.capture(content='test content', scope='my.scope', tier='episodic')`, then `memory.recall(query='test content', token_budget: 512, scope='my.scope')` | `items` non-empty; `memory_id`, `scope`, `score` fields present; **`scope` value in each returned item equals the request param value `'my.scope'`** (DES-001 §6.5 scope echo contract: scope is returned from the request params, not re-derived from the node's stored scope — a recall implementation that hardcodes `scope: ""` or omits the field would pass the field-presence check but fail this assertion) |
| IT-010b | memory.recall without scope filter (unscoped) — **Pre-condition:** call `memory.capture(content='test content', scope='any', tier='episodic')` to guarantee FTS returns at least one item (a recall with no seeded nodes returns empty items; with empty items the scope assertion is structurally untestable); then call `memory.recall(query='test content', token_budget: 512)` with no scope param | **`scope`** field in returned items equals `""` (empty string per DES-001 §6.5: "When scope is absent from the request, the wire item gets scope: \"\", meaning no scope filter was applied"); `items` non-empty (FEA-M2: pre-condition ensures this is non-vacuous) |
| IT-010c | memory.recall with non-empty seeds param — dispatch layer must thread seeds to RecallQuery (DES-001 §6.5 seeds extraction path; HC-007 golden memory.recall.json confirms seeds is a first-class wire parameter). **Pre-condition:** capture TWO memory nodes — Node A with `content='test content'`; Node B with `content='seeds bias unrelated xyz'` (record `memory_id_B`). Without seeds, a recall for query `'test content'` returns only Node A (Node B's content does not match the query; Node B is absent from FTS results). Call `memory.recall(query='test content', token_budget: 512, seeds=[<memory_id_B>])` | `items` non-empty; Node B appears in results (`memory_id_B` found in `items[].memory_id`); Node B is at rank 1 (`items[0].memory_id == memory_id_B`) — seeds biasing forces a low-FTS-affinity node into the result at the top position; a dispatch implementation that silently discards `seeds=[memory_id_B]` returns only Node A for query `'test content'` (Node B's content does not match the query, so without seeds it is absent from FTS results entirely), failing both the Node-B-appears assertion and the rank-1 assertion. Two-node design with contrasting content is required: with a single-node store, rank 1 is structurally guaranteed regardless of whether seeds are threaded through, making the assertion vacuous (FEA/DES-R16-1) |
| IT-010d | memory.recall with token_budget — dispatch layer must pass token_budget to RecallQuery (DES-001 §6.5: `let token_budget = params.get("token_budget")...` threads token_budget into RecallQuery at the same code path as scope and seeds; HC-007 golden memory.recall.json confirms token_budget is a first-class wire parameter). **Pre-condition:** capture at least 5 memory nodes with `scope='t.budget'` and `tier='episodic'`, each with content containing the unique term `'toktest_xzq'` (use distinct bodies such as `'toktest_xzq alpha'`, `'toktest_xzq beta'`, `'toktest_xzq gamma'`, etc., ensuring multiple FTS matches so token_budget has a measurable effect on result volume). This is the exact parallel of IT-020c for knowledge.recall (DES-SIG-1: IT-020c in v0.16 addressed knowledge.recall token_budget; memory.recall token_budget had the same gap) |
| IT-010e | memory.recall T2/T3 RRF score boost — REQ-003 §6: "T2 and T3 nodes receive a small score boost (configurable; default 1.1×)" (normative; no integration test currently exercises tier-relative score ordering in `rrf_fuse`). **Pre-condition:** in a fresh store, call `memory.capture(content='rrf_boost_test xzq', scope='t.rrf', tier='episodic')` → node_T1; call `memory.capture(content='rrf_boost_test xzq', scope='t.rrf', tier='semantic')` → node_T2 (both nodes have identical FTS-weighted content). Call `memory.recall(query='rrf_boost_test xzq', token_budget: 4096, scope='t.rrf')` | `items.len() == 2`; `items[0].tier == "semantic"` — the T2 node outranks the T1 node because `rrf_fuse` applies the 1.1× boost to T2 nodes; with identical FTS scores for both, the boost produces a strictly higher final score for the semantic node, placing it first. An implementation that ignores the REQ-003 §6 boost returns T1 at items[0] (see below) and fails the rank assertion (REQ-CRIT-2). **Capture order is critical:** T1 (episodic) MUST be captured FIRST and T2 (semantic) SECOND. SQLite FTS5 returns rows with equal BM25 scores in rowid-ascending order (first-inserted row has the lower rowid and ranks first). Without the 1.1× T2 boost, FTS5 places T1 at items[0] because it was inserted first (lower rowid); the assertion `items[0].tier == "semantic"` then fails, correctly detecting the absent boost. If T2 were captured first, it would rank at items[0] even without the boost, making the assertion vacuously pass against a non-boosting implementation. Any prior node in the store whose content contains 'rrf_boost_test xzq' holds a lower rowid than T1 and T2, displacing them from positions [0]/[1] and making the assertion depend on arbitrary prior content — this is why the fresh-store pre-condition is load-bearing, not boilerplate. | IT-012 | memory.reflect produces distilled_facts and node_count, and actually writes T2 nodes — **Pre-condition:** call `memory.capture(content='test reflect content', scope='test', tier='episodic')` before calling `memory.reflect(scope='test')` so the scope has known content | Response has `scope: String`, `distilled_facts: Vec<String>`, `node_count: u32`; call `memory.coverage(scope_prefix='test')` and assert `by_tier["semantic"] >= 1` (proving reflect wrote at least one T2 node in the scope — REQ-003 §2.2: "produce a distilled semantic summary… promote working memory into T2 facts"). **Do NOT use `memory.recall` to verify T2 node creation:** a correct distilling `memory.reflect` produces T2 node bodies that are summarized versions of the captured content (e.g., "An episodic memory about test reflection"), NOT the verbatim capture text 'test reflect content'. ### 3.4 — Connection Count Assertion (IT-004)

IT-004 is subprocess-level: the assertion inspects the **spawned server child process**, not the test process. An in-process variant would count the test harness's own fds and could never catch a double-open inside the production bootstrap that `main.rs` runs — the exact DEC-1 violation this test gates. Sequence: spawn `wicked-estate-mcp` (env vars → tempdir), send `initialize` plus one tools/call per domain (`SearchEntity`, `memory.coverage`, `knowledge.coverage`) to force all four stores and both engines live, then assert per store path.

```rust
fn assert_single_connection(child_pid: u32, path: &Path) {
    let canonical = path.canonicalize().unwrap();
    #[cfg(target_os = "linux")]
    let count = {
        // Count /proc/<child_pid>/fd symlinks pointing to canonical
        std::fs::read_dir(format!("/proc/{child_pid}/fd")).unwrap()
            .filter_map(|e| e.ok())
            .filter(|e| std::fs::read_link(e.path()).ok().as_deref() == Some(canonical.as_path()))
            .count()
    };
    #[cfg(target_os = "macos")]
    let count = {
        // Use lsof -p <child_pid> with exact last-field match to avoid counting .wal/.shm siblings.
        // WAL-mode opens estate.db, estate.db-wal, estate.db-shm; .contains() would count all 3.
        let canonical_str = canonical.to_str().unwrap();
        let out = std::process::Command::new("lsof").args(["-p", &child_pid.to_string()]).output().unwrap();
        String::from_utf8_lossy(&out.stdout)
            .lines()
            .filter(|l| l.split_whitespace().last() == Some(canonical_str))
            .count()
    };
    assert_eq!(count, 1, "expected exactly 1 open handle for {:?}, got {count}", path);
}
```

### 3.5 — SIGTERM/SIGINT Test (IT-007)

// Spawn wicked-estate-mcp as a child process (with env vars pointing at tempdir).
// Send SIGTERM. Wait up to 5s for exit. Assert exit code == 0.
// Assert no *.wal or *.shm files left in the tempdir.
fn assert_clean_shutdown(child: &mut Child, dir: &Path) {
    #[cfg(unix)]
